### 1. People are not the cause
- **Statement:** If the same thing would have happened with different people in those seats, the people were never the cause.
- **Layer:** Lens
- **Source:** UR, Concept 1, drawn from "Intro to Systems Thinking"
- **Source type:** Book or framework

### 2. Check the signal first
- **Statement:** Before you fix behavior, check whether the information ever arrived.
- **Layer:** Signal
- **Source:** UR, Concept 2
- **Source type:** Book or framework

### 3. Work top down
- **Statement:** When something breaks, work top down. Check the lens, then the signal, and only then, reluctantly, the structure.
- **Layer:** Lens
- **Source:** UR, Concept 3 and Part 3. Builds on Donella Meadows, "Leverage Points" (1999)
- **Source type:** Own synthesis

### 4. Ask what it does back
- **Statement:** Before you pull a lever, ask what it does back. Pushing on a system you don't understand reliably gets you the opposite of what you wanted.
- **Layer:** Lens
- **Source:** UR, Bonus: Backfiring
- **Source type:** Book or framework

### 5. Quiet excellence hides the cost
- **Statement:** The better someone performs a role nobody named, the blinder the system gets to what it costs, and the harder it breaks when they leave.
- **Layer:** Signal
- **Source:** UR, Run 1
- **Source type:** Field run

### 6. Rapport before coordination
- **Statement:** Rapport is the binding constraint, not coordination. Structure aimed at a rapport problem doesn't just miss. It eats the thing it was meant to protect.
- **Layer:** Structure
- **Source:** UR, Run 2
- **Source type:** Field run

### 7. The start decides the end
- **Statement:** The arrival window isn't a segment of the night. It's the starting condition. How the evening ends is mostly decided before it starts.
- **Layer:** Structure
- **Source:** UR, Run 3
- **Source type:** Field run

### 8. Attendance is a signal system
- **Statement:** Attendance was never loyalty. It was a signal system doing its job. A predictable event, announced predictably, needs far less apparatus than anyone assumes.
- **Layer:** Signal
- **Source:** UR, Run 4
- **Source type:** Field run

### 9. Catch value at the edge
- **Statement:** The real boundary of a group is usually wider than the one in your head. Value created at the edge disappears unless something catches it there.
- **Layer:** Signal
- **Source:** UR, Run 5
- **Source type:** Field run

### 10. Feed the channel that exists
- **Statement:** The highest-leverage outreach move isn't building a channel. It's feeding one that already exists, especially when your information fixes that channel's own missing input.
- **Layer:** Signal
- **Source:** UR, Run 6
- **Source type:** Field run

### 11. Unnamed roles leave silently
- **Statement:** A role nobody named is a role nobody has to resign from out loud. The people holding unnamed roles leave without announcement.
- **Layer:** Structure
- **Source:** UR, Run 7
- **Source type:** Field run

### 12. Turn on dormant systems
- **Statement:** Institutions are full of dormant systems: designed loops with no traffic. Turning one on is far cheaper than building one, but the first user pays an activation cost nobody after them has to pay.
- **Layer:** Lens
- **Source:** UR, Run 8
- **Source type:** Field run

### 13. Scaffolding, not character
- **Statement:** When the structure holding someone up rotates out, they drift. That's what the design produces, not a finding about their character. The group is where scaffolding gets rebuilt.
- **Layer:** Structure
- **Source:** UR, Run 9
- **Source type:** Field run

### 14. Belief before script
- **Statement:** A system built on a belief fails silently when you run it as a script. Correct mechanics aren't enough. Whatever level you're actually operating from is the system you're actually running.
- **Layer:** Lens
- **Source:** UR, Run 10
- **Source type:** Field run

### 15. A missing name or a missing signal
- **Statement:** Most group problems are a missing name or a missing signal, not a missing person.
- **Layer:** Lens
- **Source:** UR, Part 3
- **Source type:** Own synthesis

### 16. You cannot rotate what you cannot describe
- **Statement:** You cannot rotate what you cannot describe. A described role can be thanked, funded, rotated and handed off. An unnamed one can only be missed.
- **Layer:** Structure
- **Source:** UR, Part 3, and YSA handoff (content pillar line)
- **Source type:** Own synthesis

### 17. Complete one loop
- **Statement:** Do the one small thing that completes a loop, not the system that would handle every future case.
- **Layer:** Structure
- **Source:** UR, Part 3
- **Source type:** Own synthesis
